Automating with Hermes Cron

Schedule recurring tasks, chain jobs together, handle timezones, and build workflows that run while you sleep. Based on Hermes Agent for Dummies by Ken Thornton.

What You'll Learn

  • Basic cron syntax (natural language + traditional)
  • Attaching skills to scheduled jobs
  • Timezone handling (avoid 2 AM wake-up calls)
  • Chaining jobs with context_from
  • Real-world patterns: morning briefing, meeting prep, repo monitoring

Basic Scheduling

Hermes accepts both natural language and standard cron expressions:

# Natural language (recommended) /cron add "every weekday at 9am" "Summarize overnight emails" /cron add "every 15 minutes" "Check for new GitHub notifications" /cron add "daily at 7am" "Generate morning briefing" --skill morning-brief # Traditional cron syntax /cron add "0 9 * * 1-5" "Weekday 9 AM task" /cron add "*/15 * * * *" "Every 15 minutes" /cron add "0 7 * * *" "Daily 7 AM"
⚡ Pro tip

Use natural language. Hermes translates it to cron internally. Easier to read, easier to maintain.

Skill Attachment: The --skill Flag

Jobs that need a specific procedure should load a skill explicitly:

/cron add "every 1h" "Summarize new feed items" --skill blogwatcher /cron add "every weekday 8am" "Prepare meeting briefs" --skill meeting-prep /cron add "daily 6am" "Scan trending repos" --skill github-trending

The --skill flag tells Hermes to load that skill before running the job. This ensures the agent uses the right procedure for specialized tasks.

Timezone Configuration

⚠ Common pitfall

By default, Hermes uses your system timezone. If your server is UTC but you live in New York, "7 AM" runs at 2 AM your time.

Fix 1: Specify timezone in the prompt:

/cron add "every weekday at 7am Eastern time" "Morning briefing"

Fix 2: Set default timezone in ~/.hermes/config.yaml:

timezone: "America/New_York"

Now every job uses your timezone automatically.

Chaining Jobs: context_from

This is where scheduling gets powerful. One job's output becomes the next job's input:

1

Stage 1 — Gather raw data (6:45 AM)

/cron add "weekdays 6:45am" "Gather calendar, emails, weather, headlines" --skill data-gatherer
2

Stage 2 — Create visual summary (7:00 AM)

/cron add "weekdays 7:00am" "Create visual summary for top story" --skill designer --context_from data-gatherer
3

Stage 3 — Check relevant repos (7:00 AM)

/cron add "weekdays 7:00am" "Check trending repos for project relevance" --skill programmer --context_from data-gatherer

All three results land in your Telegram by 9 AM. The context_from flag passes the previous job's output as context.

Real-World Workflows

1. Meeting Preparation Bot

# Runs every 15 min, catches recently added meetings /cron add "every 15 minutes" "Check calendar for meetings in next 30 min, create one-page brief" --skill meeting-prep # Brief includes: attendees, recent emails, relevant docs, suggested questions

2. Morning Intelligence Briefing

# Multi-stage: gather → summarize → format → deliver /cron add "weekdays 6:30am" "Pull: calendar, GitHub notifications, Slack highlights, RSS feeds" --skill gatherer /cron add "weekdays 6:45am" "Synthesize into prioritized briefing" --skill synthesizer --context_from gatherer /cron add "weekdays 7:00am" "Format for Telegram, send" --skill telegram-formatter --context_from synthesizer

3. Repository Health Monitor

/cron add "daily 2am" "Run security audit, dependency check, test suite on main branch" --skill repo-health # Outputs: PDF report + GitHub issue if critical findings

4. Content Pipeline (The Humanizer)

From the book: "The Humanizer is a skill that audits any text against 30-plus known AI writing patterns and rewrites them into natural prose."

/cron add "every 30 minutes" "Check drafts folder, humanize any new markdown files" --skill humanizer

Managing Jobs

# List all scheduled jobs /cron list # Show job details /cron show "job-name" # Remove a job /cron remove "job-name" # Pause/resume /cron pause "job-name" /cron resume "job-name" # View cron logs ls ~/.hermes/cron/output/

Frequency Guidelines

⚠ API Credit Warning

A job running every 5 minutes calling external APIs will burn through credits fast. For most workflows, hourly or daily cadences are the sweet spot.

Frequency Good For Avoid For
every 5-15 min Calendar monitoring, real-time alerts Heavy API calls, LLM tasks
hourly Feed monitoring, status checks Deep research tasks
daily Reports, audits, digests, backups Time-sensitive alerts
weekly Deep reviews, cleanup, planning Anything urgent

Where Cron State Lives

~/.hermes/cron/
├── jobs.json      # All scheduled jobs with metadata
└── output/        # Per-run logs and results
    ├── job-name_2024-01-15_06-45-00.log
    ├── job-name_2024-01-15_07-00-00.log
    └── ...

Each run writes a log file. Check ~/.hermes/cron/output/ to debug failures.
